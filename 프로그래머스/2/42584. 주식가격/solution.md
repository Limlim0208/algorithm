# 프로그래머스 – 주식가격 (스택/큐) 오답 노트

## 메모
- 각 시점의 가격이 **떨어지지 않고 유지된 기간(초)**을 구하는 문제
- 핵심 키워드: **스택에 "값"이 아니라 "인덱스"를 저장**
- 시간복잡도: 이중 for문은 O(N²) → 스택 사용 시 **O(N)** (N ≤ 100,000이라 스택이 유리)

## 접근 방법
1. `answer`를 `[0] * len(prices)`로 미리 만들어 둔다.
2. 스택에는 **아직 가격이 떨어지지 않은 시점의 인덱스**만 쌓는다.
3. 각 `i`마다
   - 스택이 있고 `prices[스택 맨 위 인덱스] > prices[i]`인 **동안(while)** pop
   - pop한 인덱스 `idx`의 답을 `answer[idx] = i - idx`로 확정
   - 정리가 끝나면 현재 `i`를 push
4. 루프 후 스택에 남은 인덱스는 끝까지 안 떨어진 시점이므로 `answer[idx] = (len(prices) - 1) - idx`

## 왜 인덱스를 넣어야 할까?
- 값만 넣으면 `[1,2,3,2,3]`에서 **2초의 2와 4초의 2를 구별할 수 없다.**
- 인덱스를 넣으면 시점이 구별되고, 기간 계산(`i - idx`)도 되고, 가격은 `prices[idx]`로 언제든 꺼낼 수 있다.
- 스택 안 인덱스는 **가격이 오름차순(같은 값 포함)**으로 유지된다. 그래서 새 가격이 맨 위보다 작으면 그 밑의 것들도 연달아 확인해야 하고, 이게 `if`가 아니라 `while`을 쓰는 이유다.

## 왜 `if`가 아니라 `while`일까?
- 새 가격 하나가 들어왔을 때, **스택에 쌓여 있던 여러 시점이 한꺼번에 "떨어짐"으로 확정**될 수 있기 때문이다.
- `if`는 맨 위 하나만 검사하고 끝나지만, `while`은 **조건이 맞는 동안 계속** 꺼낸다.
- 스택 안 가격은 오름차순이라, 맨 위가 떨어졌다면 그 밑에 있던 더 비싼(또는 같은) 것들도 새 가격보다 높을 수 있다. 맨 위가 "안 떨어짐"으로 판정되는 순간 그 밑은 볼 필요가 없어서 멈춘다.

### 예시: `[3, 4, 5, 2, 6]` (정답 `[3, 2, 1, 1, 0]`)
- `i=3`(가격 2)이 들어올 때 스택은 `[0, 1, 2]` (가격 3, 4, 5)
- 2는 5, 4, 3보다 모두 낮다 → **인덱스 2, 1, 0이 전부 이 시점에 떨어짐**

| 방식 | 처리 결과 | 최종 answer |
|---|---|---|
| `while` | 2, 1, 0을 모두 pop → `answer[2]=1`, `answer[1]=2`, `answer[0]=3` | `[3, 2, 1, 1, 0]` ✔ |
| `if` | 2만 pop → `answer[2]=1`. 1, 0은 스택에 남음 | `[4, 3, 1, 1, 0]` ✘ |

- `if`로 하면 인덱스 0, 1은 **이미 떨어졌는데 "끝까지 안 떨어진 것"으로 처리**돼서, 마지막 `for`에서 기간이 `len(prices)-1-idx`로 잘못 계산된다.

### 한 줄 정리
- **`while` = 이번 가격으로 인해 확정되는 시점을 하나도 빠짐없이 정리하기 위해서.**
- 정리가 끝난 뒤(`while` 밖)에 현재 인덱스 `i`를 push한다.

## 내가 틀린 점
| # | 틀린 코드 | 문제 | 고친 방향 |
|---|---|---|---|
| 2 | `stack.append(prices[i])` | 가격을 넣어서 기간 계산 불가 | `stack.append(i)` (인덱스) |
| 3 | `answer[i] = i - stack[-1]` | 확정되는 건 **꺼낸 인덱스**의 답 | `idx = stack.pop()` 후 `answer[idx] = i - idx` |
| 4 | `if not stack:` 블록 | `while`의 `stack and ...`가 이미 처리 | 불필요하므로 삭제 |
| 5 | 종료 후 처리 누락 | 남은 인덱스의 답이 0으로 남음 | 마지막 `for`로 `len(prices)-1-idx` 채우기 |
| 6 | `stack.append(i)`가 `while` 안쪽 | 스택이 비면 `while`이 안 돌아 push가 영원히 안 됨 → `[0,0,0,0,0]` | `while`과 **같은 들여쓰기**로 이동 |
| 7 | `stack[-1] > prices[i]` | 인덱스와 가격을 비교함 | `prices[stack[-1]] > prices[i]` |


## 기억할 것
- "**나중에 값이 바뀌는 시점을 찾는 문제**" → 스택에 **인덱스**를 쌓는다 (비슷한 유형: 다음 큰 수 등).
- 스택에서 꺼내는 건 `while`, 꺼낸 뒤 현재 값을 넣는 건 `while` **밖**.
- 스택에 인덱스를 저장하면 값은 `prices[stack[-1]]`로 접근.
