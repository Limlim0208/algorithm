> 메모: 처음에는 첫 행/첫 열을 전부 1로 채우고 시작했는데, 웅덩이가 첫 행/열에 있으면 그 뒤 칸까지 1이 되어 답이 틀렸다.  
 첫 행/열도 다른 칸과 **같은 규칙**(위 + 왼쪽)으로 처리하면 별도 초기화가 필요 없다.  
> `break`와 `continue`를 헷갈리지 말자. 웅덩이 칸 하나만 건너뛰려면 `continue`다.  
> 문제에서 주어진 좌표 순서와 코드의 인덱스 순서(행, 열)가 다를 수 있다. 입력을 받자마자 변환해 두면 실수가 줄어든다.  

# 접근 방법

## 동적 계획법 (Dynamic Programming, DP)

큰 문제를 작은 문제로 나누어 풀고, 작은 문제의 답을 저장해 두었다가 큰 문제를 풀 때 재사용하는 방법이다.

**DP를 쓸 수 있는 조건**
1. **최적 부분 구조**: 큰 문제의 답이 작은 문제들의 답으로 구성된다.
2. **중복되는 부분 문제**: 같은 작은 문제를 여러 번 풀게 된다. 한 번 계산한 값을 저장하면 중복 계산을 피할 수 있다.  

### 구현 방식

| 방식 | 설명 | 구현 |
|------|------|------|
| Bottom-up (타뷸레이션) | 작은 문제부터 차례로 채워 나간다 | 반복문 + 배열 |
| Top-down (메모이제이션) | 큰 문제에서 시작해 재귀로 내려가고, 계산한 값을 저장한다 | 재귀 + 딕셔너리/배열 |

이번 풀이는 Bottom-up 방식이다.

## 격자 경로 문제에 적용하기

집(왼쪽 위)에서 학교(오른쪽 아래)까지 오른쪽, 아래쪽으로만 이동할 때 가능한 경로의 수를 구하는 문제다. 웅덩이 칸은 지나갈 수 없다.

**핵심 아이디어**  
어떤 칸에 도착하는 방법은 **바로 위 칸에서 내려오거나, 바로 왼쪽 칸에서 오는 것** 두 가지뿐이다. 따라서 그 칸까지의 경로 수는 두 칸의 경로 수를 더한 값이다.

**점화식**
```
dp[i][j] = dp[i-1][j] + dp[i][j-1]
```

**초기값과 예외 처리**
- 시작 칸: `dp[0][0] = 1`
- 웅덩이 칸: `dp[i][j] = 0` (이 칸을 지나는 경로가 없으므로 0이 뒤쪽 칸으로 전파된다)
- 경계 밖(`i == 0` 또는 `j == 0`)은 더하지 않는다

**시간복잡도**: O(m * n)

**참고: 웅덩이가 없을 때는 조합으로도 풀 수 있다**  
가로로 m-1번, 세로로 n-1번 이동하므로 `C(m+n-2, m-1)`이다. 웅덩이가 있으면 DP가 더 일반적이다.

## 처음 작성한 코드의 문제점

```python
def solution(m, n, puddles):
    route=[[0]*m for _ in range(n)]
    
    for i in range(m):
        route[0][i]=1
    for j in range(n):
        route[i][0]=1
    
    for i in range(1, n):
        for j in range(1, m):
            if [i,j] in puddles:
                break;
            route[i][j]=route[i-1][j]+route[i][j-1]
            
    return route[m-1][n-1]
```

### 1. 인덱스 에러 (out of range의 직접 원인)

- `route[i][0]=1`: 두 번째 반복문의 변수는 `j`인데 `i`를 썼다. 이때 `i`는 앞선 반복문이 끝난 뒤의 값인 `m-1`이다. `route`의 행 개수는 `n`이므로 `m > n`이면 범위를 벗어난다. → `route[j][0]=1`
- `return route[m-1][n-1]`: `route`는 **n행 m열**이므로 `route[n-1][m-1]`이어야 한다.

### 2. 로직 문제 (에러는 안 나지만 답이 틀림)

- **`break` 사용**: 웅덩이를 만나면 그 행의 나머지 칸을 전부 건너뛰어 버린다. 웅덩이 칸만 건너뛰려면 `continue`를 써야 한다.
- **첫 행/첫 열을 무조건 1로 초기화**: 웅덩이가 첫 행/열에 있으면 그 뒤 칸들도 1이 되어 틀린 값이 된다. 웅덩이 이후 칸은 0이어야 한다.
- **웅덩이 좌표 순서 불일치**: 프로그래머스의 `puddles`는 `[열, 행]`(x, y) 순서이고 **1부터 시작**한다. `[i, j]`(0-based 행, 열)와 직접 비교하면 맞지 않는다.
- **나머지 연산 누락**: 문제에서 `1,000,000,007`로 나눈 나머지를 반환하라고 했다.
- **`in puddles` 탐색 비용**: 리스트에서 `in`은 O(len)이라 매 칸마다 호출하면 느리다.

## 수정한 코드에서 적용한 사항

```python
def solution(m, n, puddles):
    puddle_set = {(y - 1, x - 1) for x, y in puddles}  # (행, 열)로 변환
    route = [[0] * m for _ in range(n)]
    route[0][0] = 1

    for i in range(n):
        for j in range(m):
            if (i, j) in puddle_set:
                route[i][j] = 0
                continue
            if i > 0:
                route[i][j] += route[i - 1][j]
            if j > 0:
                route[i][j] += route[i][j - 1]
            route[i][j] %= 1_000_000_007

    return route[n - 1][m - 1]
```

| 문제점 | 수정 내용 |
|--------|-----------|
| 인덱스 오타 (`route[i][0]`) | 첫 행/열 초기화 반복문 자체를 없앰 |
| 반환 인덱스 `route[m-1][n-1]` | `route[n-1][m-1]`로 수정 (n행 m열) |
| `break` | `continue`로 변경, 웅덩이 칸은 `0`으로 명시 |
| 첫 행/열 전부 1로 초기화 | `route[0][0] = 1`만 두고, 나머지는 `i > 0`, `j > 0` 조건으로 같은 규칙 적용. 웅덩이 뒤쪽 0이 자연스럽게 전파됨 |
| 좌표 순서 / 1-based | `{(y - 1, x - 1) for x, y in puddles}`로 (행, 열) 0-based 변환 |
| `in puddles` 리스트 탐색 | `set`으로 바꿔 탐색을 O(1)로 개선 |
| 나머지 연산 누락 | 매 칸마다 `%= 1_000_000_007` 적용 (값이 커지는 것을 방지) |

### 참고
- `if i > 0` / `if j > 0` 조건으로 경계를 처리하면 첫 행/열을 따로 초기화하지 않아도 되어 코드가 간결해진다.
- 반복문 변수명(`i`, `j`)과 배열 크기(`n`, `m`)의 대응 관계를 주석으로 적어 두면 인덱스 실수를 줄일 수 있다.
